# Firehouse Deluxe

## Что делаем

- Делаем шуточный ремейк **Fisher-Price: Firehouse Rescue** для NES.
- Игра полностью 2D. Для текущего прототипа пожарной машины используется вид сверху и автомобильное управление в духе GTA 1: газ, торможение, задний ход и плавные повороты на любой угол.
- Визуальный стиль — **пиксельная графика** с сохранением шуточного характера ремейка.
- Ориентир для графики — оригинальная игра. Текущие уровни собираем из тайлов; готовая картинка оригинальной карты не является основой тайлового уровня.
- Пиксельные ассеты сохранять чёткими: без размытия и сглаживания при импорте, с фильтрацией Point. Сохранять исходники в оригинальном разрешении.
- Временные условные спрайты допустимы для прототипов, но не определяют финальный стиль.
- Юмор и намеренная кривизна допустимы в художественной подаче. Управление, поведение игры и качество кода должны быть понятными и предсказуемыми.

## Техническая основа

- Unity **6.3 LTS**, текущая версия проекта — `6000.3.17f1`.
- Universal 2D / URP, C#, установленный Unity Input System.
- Основные игровые файлы: `Assets/FirehouseDeluxe/`.
- Рабочая сцена — `Assets/Scenes/RoadPlayground.unity`, открываемая меню `Firehouse Deluxe → Tile Editor`. Старые тестовые сцены удалены; не восстанавливать их без отдельной задачи.
- Уровень строится настоящими тайлами 8×8 пикселей, без привязки к временной картинке карты. При 4 Pixels Per Unit размер клетки Grid — 2×2 единицы Unity, без сдвига в пиксель.
- Проезд — только пустые клетки тайлмапы, через которые виден чёрный фон камеры. Любой нарисованный тайл — препятствие, независимо от цвета. Дороги создавать ластиком, удаляя тайлы.
- В Tile Palette `Road Palette`: чёрный `Obstacle` и зелёный `Ground` — препятствия. Обычные Tile-ассеты в `Assets/FirehouseDeluxe/Tiles/` автоматически получают `Collider Type = Sprite`: коллизия строится по физическому силуэту спрайта, с учётом его прозрачных участков. Не создавать исключения для проезжих нарисованных тайлов.
- Для автомобиля: движение в плоскости XY, нос спрайта направлен вдоль локальной +Y, поворот вокруг Z, физика через `Rigidbody2D`.
- Не добавлять сторонние пакеты, если задачу разумно решить имеющимися средствами. Существенные зависимости согласовывать с пользователем.

## Код: понятность и DRY

- Писать простой, читаемый код с понятными именами и небольшой областью ответственности у каждого компонента.
- Соблюдать DRY: общая логика должна иметь одно место определения. При этом не создавать абстракции ради устранения случайно похожих строк.
- Использовать минимальную архитектуру, достаточную для текущей задачи. Не добавлять системы и универсальные фреймворки на вырост.
- Новые команды меню, контекстные пункты и кнопки редактора добавлять только по прямой просьбе пользователя. Не добавлять их по собственной инициативе, в том числе для открытия сцен и действий, доступных стандартными средствами Unity.
- Не добавлять команды миграции и контекстные пункты вроде `Use Shared Camera` для замены объектов на prefab. Использовать стандартные операции Unity; сохранность открытой сцены не является поводом обходить этот запрет собственной командой.
- В игре должна быть одна постоянная камера на все сцены, а не отдельные экземпляры prefab по сценам. `PersistentGameCamera` создаёт её перед загрузкой первой сцены из `Assets/FirehouseDeluxe/Resources/MainCamera.prefab` и сохраняет через `DontDestroyOnLoad`. Общие настройки: Reference Resolution = 256×240, Assets PPU = 4, Orthographic Size = 30 (из сохранённой RoadPlayground на 2026-10-26). В сценах — только `Camera Anchor` с `SceneCameraAnchor` и, для карты, `VehicleFollowCamera`. Не менять разрешение камеры ради фоновой картинки.
- Разделять ввод, игровую логику и отображение там, где это упрощает изменение и понимание кода.
- Параметры, которые нужно подбирать на глаз и по ощущениям, открывать в Inspector через сериализуемые поля. Не дублировать настройки в нескольких местах.
- Физику обновлять в `FixedUpdate`, считывание ввода — в соответствии с настройками Input System, следование камеры — в `LateUpdate`.
- Комментарии должны объяснять причины и неочевидные решения, а не пересказывать код.
- Не проводить несвязанный рефакторинг и не перезаписывать пользовательские сцены, ассеты или настройки без необходимости для задачи. Сохранять существующие `.meta` и ссылки на ассеты.
- Не создавать резервные копии, снимки сцен и дополнительные файлы восстановления по собственной инициативе. Делать это только по прямой просьбе пользователя.
- Не редактировать файл открытой пользовательской сцены на диске: в Unity могут оставаться несохранённые изменения, которые исчезнут после Reload. Изменения объектов такой сцены пользователь выполняет в Unity; при необходимости подготовить отдельную команду редактора с Undo, применяемую к текущей сцене без её перезагрузки. Не считать сохранённый файл актуальным состоянием открытой сцены.

## Проверка и работа с пользователем

- **Ручное тестирование игры в Unity выполняет пользователь.** Он проверяет геймплей, визуал и ощущения от управления.
- После изменения давать короткую инструкцию: какую сцену открыть, что нажать и какое поведение проверить. Указывать, где находятся доступные настройки в Inspector.
- Не запускать Unity ради тестирования, не открывать второй редактор и не создавать отдельные копии проекта для проверок по собственной инициативе. Такие проверки выполнять только по явной просьбе пользователя.
- По умолчанию не добавлять и не запускать автоматические игровые тесты; необходимость таких тестов обсуждать отдельно. Наличие тестов в проекте само по себе не означает просьбу их запускать.
- Доступные проверки исходников и ошибок компиляции можно выполнять без запуска отдельной Unity. Не выдавать проверку кода за проверку игры в Play Mode.
- Чётко сообщать, что реализовано, что фактически проверено и что предстоит проверить пользователю.
- Обсуждать проект с пользователем на русском языке.

Машина импортируется с 16 PPU против 4 PPU фона — размер уменьшен ровно в 4 раза относительно базовой плотности, исходная картинка не изменена. Point, без сжатия. Положение экземпляра задаёт пользователь в Scene; не сбрасывать его при изменении prefab. Изменения применены к открытому экземпляру через Unity без перезагрузки сцены, резервных копий и новых команд; сцену сохраняет пользователь Ctrl+S.
- Машина миниигры движется по X на A/D или ←/→. `SideViewVehicleKeyboardInput` читает ввод, `SideViewVehicle` обновляет скорость через Rigidbody2D в FixedUpdate: плавный разгон и смена направления, короткий накат при отпускании клавиш. Компоненты добавлены в prefab и появились на открытом экземпляре без изменения пользовательской позиции. Play Mode и автоматические игровые тесты не запускались; ощущения проверяет пользователь.
- В открытой `WindowRescue` создан `Window Rescue` с `WindowRescueRound` и четырьмя областями `Windows/Window 1–4`. Экранные надписи счётчика и завершения удалены по просьбе пользователя; не добавлять их обратно без отдельной задачи. Пользователь расставляет области по фону через Transform; размер задаётся Box Collider 2D. Персонаж появляется в нижнем центре области (ноги на подоконнике). Цель — 2 спасённых. Падение не увеличивает цель и не меняет число уже спасённых: после исчезновения упавшего персонажа появляется новая попытка спасения. Следующий персонаж выбирает случайное окно, отличное от предыдущего; после двух успешных спасений новые персонажи не создаются.
- `Prefabs/RescuePerson.prefab` использует целые `jo_idle` и `jo_stress` (64×112, Single, Bottom Center, 16 PPU, Point, без сжатия). Исходные PNG не уменьшались; плотность 16 PPU даёт уменьшение в 4 раза относительно фона 4 PPU. В ожидании и при спуске — idle, при падении — stress. `RescuePerson` двигает кinematic Rigidbody2D в FixedUpdate; Descent Speed и Fall Acceleration доступны в Inspector prefab.
- У `RescueFireEngine` добавлены `Ladder Pickup` (Box Collider 2D, Is Trigger, `RescueLadder`) и `Ladder End` — точка завершения спуска. Пользователь может передвинуть обе точки и изменить коллайдер в Inspector. Касание запускает автоматический спуск после остановки машины с учётом инерции; движение или новое нажатие A/D/стрелок во время спуска вызывает падение. Внизу лестницы персонаж исчезает и засчитывается; упавший исчезает ниже Fall Despawn Y и не засчитывается. Четыре окна и ссылки созданы внутри уже открытой Unity с Undo, без изменения файла открытой сцены, резервных копий и новых команд меню. Пользователь должен расставить области и сохранить Ctrl+S. Закрытая RoadPlayground сохранена редактором; открытая WindowRescue оставлена с несохранёнными изменениями и Undo — пользователь сохраняет её Ctrl+S.
